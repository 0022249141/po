# Canonical MetaTrader 5 UTC Export Protocol

**Status:** operational tooling ready; canonical UTC bundles can be captured locally, validated, and converted into compact promotion records before repository registration.

## Purpose

Create a new XAUUSD research bundle whose timestamps, broker/server identity, symbol specification, cutoff, file hashes and closed/forming state are bound in the same export run.

This protocol is the preferred resolution path for future session-sensitive XAUUSD research.

## Why a new canonical export is preferred

The existing `XAUUSD_o` bundle is internally consistent but its timestamps are source-local and the exact export terminal/timezone history was not captured with the raw files. A later terminal observation can support a timebase candidate, but it cannot retroactively prove the historical bundle's source clock.

The canonical exporter therefore creates **new data** directly through the MetaTrader5 Python API and records the evidence in `binding_manifest.json`.

It does **not** rewrite or retroactively verify the legacy source-local bundle.

## Authoritative timestamp basis

MetaQuotes documents that MetaTrader 5 stores tick and bar open times in UTC and that data obtained through the Python integration has UTC time. The exporter uses timezone-aware UTC request datetimes and converts returned epoch timestamps directly to ISO-8601 UTC.

Primary references:

- `https://www.mql5.com/en/docs/python_metatrader5/mt5copyratesrange_py`
- `https://www.mql5.com/en/docs/python_metatrader5/mt5copyticksrange_py`

Project source id: `metatrader5_python`.

## Exporter

`tools/export_mt5_utc_bundle.py`

Properties:

- read-only terminal access;
- requires an already logged-in MT5 terminal;
- exact symbol is required explicitly;
- exports H1, M15 and M5 bars plus optional ticks;
- records `company` and `server` from account metadata;
- records terminal version and symbol specification;
- records an explicit UTC export cutoff;
- marks each bar closed/forming causally from its UTC open epoch plus timeframe duration;
- computes SHA-256 for every exported market-data file;
- runs self-validation before declaring success;
- does not store the account login number or password;
- does not call any order/trading function.

If the requested symbol is absent, the exporter lists deterministic XAU/GOLD candidates from the connected terminal rather than silently substituting another symbol.

## Output

Each run creates a directory and ZIP containing:

- `<symbol>_H1_bars_utc.csv`
- `<symbol>_M15_bars_utc.csv`
- `<symbol>_M5_bars_utc.csv`
- `<symbol>_ticks_utc.csv` when ticks are enabled
- `binding_manifest.json`
- `quality_report.json`
- `validation_report.json`

Bulk output remains local/external and is ignored by Git. Only reviewed manifests/reports should later be promoted into repository records.

## Binding manifest

Required evidence includes:

- exporter id/version;
- `timestamp_semantics = utc_from_metatrader5_python_api`;
- export time in UTC;
- broker company/server;
- exact symbol and symbol specification;
- terminal version/connectivity;
- per-file row count, first/last UTC timestamps and SHA-256;
- explicit statement that the binding applies only to files generated in that run.

## Validation

The exporter self-validates the freshly generated bundle before reporting `SUCCESS`. Manual re-validation is also available:

```powershell
py tools\validate_mt5_utc_bundle.py "<bundle-folder>\binding_manifest.json"
```

A passing hash validation proves that the manifest still refers to the same generated bytes. It does not by itself establish trading edge or data completeness.

## Promotion preparation

A validated local bundle is not automatically a repository dataset. Create a compact, reviewable promotion record from the exact manifest:

```powershell
py tools\prepare_mt5_utc_promotion.py "<bundle-folder>\binding_manifest.json"
```

The command writes `<bundle-folder>\promotion_record.json` and prints a compact summary containing:

- deterministic dataset id;
- exact symbol;
- broker/feed identity;
- verified UTC timebase status;
- named-session eligibility;
- session-policy id;
- SHA-256 of the binding manifest;
- number of bound market-data files.

The promotion record is derived only after the source manifest and every referenced market-data file pass hash validation. It does not copy raw market data into Git.

## Session consequence

A valid canonical UTC bundle removes the need to infer the **data timestamp timezone** from broker chart time. Its input timebase can be classified as `verified_utc` because the API returns UTC epoch timestamps and the exact exported bytes are bound to the manifest.

Named research sessions may then be classified downstream through `config/session-policies/xauusd-major-sessions.yaml`, which uses IANA zones and their own DST rules (`Asia/Tokyo`, `Europe/London`, `America/New_York`).

That downstream session policy is a separate research convention: it is not an exchange-hours claim, broker-maintenance schedule, ICT kill-zone definition, or trading signal.

## Legacy bundle boundary

The current source-local bundle `xauusd_o_mtf_20260903_0922` remains `candidate`. A successful canonical UTC export creates a new verified-timebase dataset; it does not change the historical truth status of the old bundle.
