## DST behavior verified from the policy

The engine uses IANA timezone rules rather than fixed offsets.

Examples:

- London 08:00 local = 08:00 UTC in winter and 07:00 UTC in summer.
- New York 08:00 local = 13:00 UTC in winter and 12:00 UTC in summer.
- Tokyo 09:00 local = 00:00 UTC in both winter and summer.
- On `2026-03-16`, after the US DST switch but before the UK switch, London opens at 08:00 UTC while New York opens at 12:00 UTC. The temporary US/UK DST mismatch is preserved rather than flattened.

## Observed overlap behavior

The policy intentionally allows overlaps. On closed M5 bars in the reviewed dataset, the observed classifications include both:

- Asia/Tokyo ↔ London overlap;
- London ↔ New York overlap.

The overlap changes in UTC when DST rules change. This is expected policy behavior, not a timestamp inconsistency.

## Verdict

**NAMED-SESSION-POLICY: OPERATIONAL; DATASET SESSION COVERAGE: QUALIFIED PER INSTANCE, NOT ASSUMED COMPLETE.**

Approved:

- deterministic London/New York/Asia-Tokyo labeling on the canonical UTC dataset;
- DST-aware session research;
- overlap analysis;
- per-session completeness filtering before downstream analysis;
- descriptive session-conditioned features using only closed bars.

Not approved by this audit alone:

- ICT kill-zone substitution;
- automatic holiday labeling;
- moving session boundaries to match broker maintenance gaps;
- treating an incomplete session as fully observed;
- inferring exchange order flow, centralized volume, or dealer inventory;
- any trading edge or profitability claim.

## Downstream rule

Any strategy or descriptive statistic conditioned on a named session must explicitly choose one of these data policies:

1. `complete_only` — use only session instances with every expected bar present;
2. `allow_incomplete_with_flag` — retain incomplete instances but carry the completeness flag into analysis;
3. `coverage_edge_excluded` — always exclude dataset-start or current-cutoff partial instances from full-session statistics.

The project default for future backtests should be `complete_only` unless the frozen Strategy Specification states otherwise.
